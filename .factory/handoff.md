## What shipped

- A Rust CLI that scans one workflow file or every workflow under
  `.github/workflows` without running workflow steps.
- Inventories for actions, runner labels, job images, service images,
  permissions, shells, commands, and GitHub-hosted path assumptions.
- Versioned profiles for GitHub-hosted Ubuntu, `act`, generic Linux, and a
  self-hosted Linux runner.
- Static compatibility rules with portable, review, and nonportable outcomes.
- Opt-in host probes gated by both `--probe` and `--sandbox`. Observed failures
  are labelled separately from static findings.
- Terminal, JSON, Markdown, and SARIF reports. Nonportable reports exit with
  code 1; invalid input exits with code 2.
- A `demo` command that copies the bundled release workflow into a new
  temporary directory and prints the saved Markdown report path.
- A Vite landing and docs site with `/demo`, `/privacy`, `/terms`, and a styled
  404 state. The browser demo is generated by the real Rust CLI during build.
- Night-market neon art, self-hosted fonts, responsive layouts, keyboard route
  focus, saved scroll positions, reduced motion, and Azure Static Web Apps
  security and cache headers.

The bundled benchmark produces 10 static errors against the generic Linux
profile. This exceeds the brief's target of 8 out of 10 known failures.

## Known limits

- This is static readiness evidence, not a workflow executor or pass guarantee.
- Expressions, custom actions, and reusable workflows are inventoried but not
  expanded into their runtime behavior.
- Bundled profiles are documented snapshots dated `2026-08`; runner image
  changes require a new profile version.
- Host probes observe the machine running the CLI. They do not connect to a
  remote target runner.
- Lighthouse lab runs do not emit field INP. Total Blocking Time was 0 ms, and
  browser tests cover the available interactions.
